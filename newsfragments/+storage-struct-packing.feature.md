Struct and tuple fields narrower than a word (`bool`, `u8` to `u128`, `i8` to `i128`) are now packed into shared storage and transient storage slots the way Solidity packs struct members: in declaration order from the low-order end of a slot, a field that does not fit the rest of the slot starts the next one, and nested structs, arrays, enums, `Address` and other 32-byte values take whole slots, as does the field after them. Narrow signed values in storage, packed or not, are stored as their own two's-complement bytes instead of sign-extended to the whole slot. This applies to contract fields, `StorPtr`/`TStorPtr` targets and `StorageMap` entries, so a struct in a map is laid out like a struct in a Solidity `mapping`. Writing a whole struct composes each slot and stores it once without loading it first, reading one loads each slot once, and writing a single packed field updates only its bytes. Packed fields can still be read, assigned, updated in place (`s.a += 1`), passed on as effects (`with (mut s.a) { ... }`) and used as `mut self` receivers; references to whole structs stored in values can also project their packed fields. Directly storing a provider reference to a field that shares its slot (e.g. `Option::Some(mut s.a)`) is still rejected. This changes the storage layout of existing structs with narrow fields, and the layout hover shows the bytes of a slot each packed field occupies.
