`StorageMap` now stores every value in the native storage layout of its type, for `get`/`set` as well as for entry pointers, so both always see the same slots. `get` requires `V: Copy`; `set` also accepts non-`Copy` values. `StorageHeap<T>` requires only `T: Ord + Copy` and supports multi-word elements; each heap step reads and writes whole elements, so its storage cost grows with the element's slot count. The `std::evm::WordRepr` trait and the `std::evm::word` module have been removed. Key encodings and slot derivation are unchanged; integer keys now use `core::num::IntWord`. Migration: remove `WordRepr` impls. A type whose custom encoding differs from its native layout must be migrated, either by declaring narrow fields so that native packing yields the same bytes (fields are placed in declaration order from the low-order end of the slot) or by storing an explicitly encoded `u256`. Enums and `Address` are not packed yet, so a value containing them can no longer be compressed into fewer slots. Map values of a narrow signed type (`i8` to `i128`) are now written as their own two's-complement bytes instead of sign-extended to the whole slot, like in Solidity; words written in the old form still read back as the same value.
