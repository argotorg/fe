Added `std::evm::erc20::Erc20`, an ERC-20 token with EIP-2612 permit after Solady's `ERC20`, as a storage component: a contract keeps it in a field and answers the standard messages `IErc20` and `IErc20Permit` by delegating to its methods, so there is no inheritance and no virtual hooks. Each method's effects show what it touches (`transfer` uses `Ctx` and `mut Log`, `mint` and `burn` only `mut Log`), and `mint` and `burn` leave access control to the contract. Failures revert with Solady's custom errors, an allowance of `u256::max()` is never spent, and `Transfer` and `Approval` events match Solidity's. A permit is checked by `verify_permit`, which returns a `VerifiedPermit` only `std` can construct, and applied by `permit`, which accepts nothing else; malleable signatures are rejected.
