A call may give only some of its callee's generic arguments. They fill the parameters from the left, and each parameter left out takes its default or is inferred, so `op<1>(c)` calls `fn op<const N: u64, F: Rules>(_ c: Cursor<F>)` with `F` inferred from `c`. This applies to function, method and associated function calls, such as `self.op_push<1>(c, mut tracer)` and `T::make<1>(c)`. A `_` among a call's generic arguments is inferred, even for a parameter with a default, so later arguments can be given while earlier ones are inferred: `len<_, 3>(xs)`. `_` is only allowed as a whole generic argument of a call, not in signatures or in the types a body writes. A call that leaves a generic parameter uninferred now names it, with the arguments that would give it, as in "cannot infer the type parameter `F` of `op`" and "consider giving it explicitly: `op<1, F>`".
