`fe check`, `fe test` and `fe build` now report type errors in the built-in `core` and `std` ingots when the code being compiled reaches the affected function, for example while editing `ingots/core` with a debug build of `fe`. Previously such errors surfaced as an internal error like "semantic body is blocked by upstream causes" or "cannot structurally repack `u256` as `usize`", or `fe check` passed and only code generation failed. The real diagnostics are now shown under "Errors in dependency" with the file in `core` or `std`.
