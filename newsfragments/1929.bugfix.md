A `ref` or `mut` binding of a part of a named product parameter now opens an access, as a binding on any place does. `let (a, mut b) = s; let (c, mut d) = s` with overlapping uses, and `let (a, mut b) = s; bump(s); b += a`, are now access conflicts instead of being accepted. `let x = ref s.1` and `let (ref x, ref y) = s.1` no longer fail with an internal error, nor does `let i = s.1` for a `Copy` struct behind a `mut` part. Reading a non-`Copy` part with `let c = s.1` now moves it, as through any access.
