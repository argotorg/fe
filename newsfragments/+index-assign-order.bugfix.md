An assignment through `IndexMut`, such as `a[k] = carry` on a `MemArray<u256>` parameter, is no longer rejected as a borrow conflict when `carry` is a `let mut` local and the array is written more than once, for example in a loop that reassigns `carry`. An assignment now evaluates its right-hand side before the assigned place, as Rust does, so `index_mut` is called after the value is read. This changes the order of side effects: in `a[f()] = g()`, `g()` now runs before `f()`, and in `a[k] = x` the value of `x` is read before the index expression runs. Compound assignment such as `a[k] += carry` still evaluates the place first and is still rejected in this situation.
