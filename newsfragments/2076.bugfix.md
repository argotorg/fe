The ABI function name of a msg variant is now read from the evaluation that fixes its selector. A selector reached through a trait default, a generic const fn or a const fn wrapper previously gave the right numeric selector but no ABI entry, and its signature checks did not run. The malformed-signature (9-0009), argument-count (9-0007) and field-type (9-0006) checks now apply to these selectors, and `[u8; N]` arguments of `std::abi::sol` now work.

The signature belongs to the value that a `std::abi::sol` call returned. A value computed from it (arithmetic, a cast, including a cast through a newtype) or read from a constant aggregate has no signature, as before: the numeric selector is unchanged and the arm is skipped with a warning. Programs that compiled before can now fail only when such a selector, or a `std::abi::sol` argument that is a const string, gives a signature that is malformed or whose argument count or types do not match the fields.
