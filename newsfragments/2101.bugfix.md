A `with` block whose provider is a projection's result, such as `with (Frame = indented(4)) { .. }`, now holds the projection until control leaves the block, and its slide runs there. Before, the projection ended at the last call in the block that took the provider, or at once if none did, so code in the block that named the projected place (the function's own `frame` effect, or the local a method projection was taken from) was accepted and saw the place after the slide had undone the block's change. That code is now an access conflict, as is `with (Frame = frame.clipped(a)) { with (Frame = frame.clipped(b)) { .. } }` on a local `frame`; to nest, project the enclosing block's provider with a projection that takes `Frame` as an effect.
